# Размещение на GitHub

Папка подготовлена для отдельного приватного репозитория. Сам запуск приложения ничего на GitHub не загружает.

## Первая загрузка

Нужны [Git](https://git-scm.com/downloads) и [GitHub CLI](https://cli.github.com/). Один раз войдите в аккаунт командой `gh auth login`. Не записывайте токен в файлы проекта.

Откройте PowerShell в этой папке. Сначала посмотрите, какие файлы будут добавлены:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\publish-github.ps1 -Repository requests-automation
```

Когда решите загрузить проект, выполните ту же команду с `-Publish`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\publish-github.ps1 -Repository requests-automation -Publish
```

Скрипт создаст локальный коммит, приватный репозиторий в активном аккаунте GitHub и отправит код. Других людей он не приглашает. Данные из `data/` не добавляются. До передачи проверьте, что в исходниках и примерах нет ваших личных данных.

Если Git попросит имя и email, задайте свои значения (email виден в коммите; можно взять GitHub noreply из настроек аккаунта):

```powershell
git config --global user.name "ВАШЕ ИМЯ"
git config --global user.email "ВАШ EMAIL ИЛИ GITHUB NOREPLY"
```

Эти две команды меняют настройки Git для пользователя; выполните их только если такие настройки ещё не заданы. Скрипт сам их не меняет.

## Если загрузка прервалась

Скрипт не удаляет локальный коммит и не перезаписывает историю. Если папка уже содержит `.git`, он остановится.

- Если репозиторий на GitHub ещё не создан: из папки проекта выполните `gh repo create requests-automation --private --source . --remote origin --push`.
- Если репозиторий и `origin` уже созданы, но отправка не закончилась: `git push -u origin main`.
- Если указанное имя занято, выберите другое. Не удаляйте существующий репозиторий ради повторного запуска.

## Как передать работодателю

Для приватного репозитория пригласите человека через **Settings → Collaborators → Add people**. После принятия приглашения он сможет открыть README и скачать **Code → Download ZIP**. Одна ссылка без приглашения доступа не даёт. В личном приватном репозитории collaborator получает также право записи; для передачи без доступа к репозиторию отправьте ZIP отдельно.

Чтобы проверить приложение, получатель распаковывает ZIP и выполняет шаги из README. GitHub хранит код; приложение запускается на его компьютере.

Команда загрузки соответствует [документации GitHub CLI](https://cli.github.com/manual/gh_repo_create). Создание репозитория и реальная отправка в рамках подготовки не выполнялись: проверен режим просмотра и синтаксис скрипта.
